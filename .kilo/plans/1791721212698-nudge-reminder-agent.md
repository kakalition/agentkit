# Nudge — a general reminder agent on agentkit

Build a new agent repo at `~/Workspaces/nudge` using the sibling agents
(`Artemis`, `calliope`) as the structural template. It manages **general
reminders**: recurring (`cron`) *and* one-off (`once`). When a reminder fires, the
agent **rewrites the delivered message (the "nudge") in the voice defined by
`SOUL.md`** — i.e. the message is generated by the model with the SOUL persona
composed into its instructions, not emitted as a static string.

## Confirmed decisions

- **Name:** `nudge` — repo `~/Workspaces/nudge`, package `src/nudge`, `agent_name = "nudge"`, home `~/.agentkit/nudge`, DB `nudge.db`.
- **Delivery:** durable local **outbox** always (readable via CLI `nudge inbox` and the built-in operator web UI), **plus Telegram** to the owner chat when `TELEGRAM_BOT_TOKEN` is configured.
- **The nudge = LLM rewrite:** each fire composes one short message via a PydanticAI agent whose instructions are `compose_instructions(load_soul(settings), NUDGE_INSTRUCTIONS)`. A deterministic fallback template is used if the model call fails.
- **Storage:** reuse agentkit infra only — reminders are `scheduled_jobs` rows with `task="nudge"` and `args={"text":…, "target":…}`; the outbox is a `nudge:outbox` conversation. **No domain tables**, so the stock web UI (Schedules + Conversations tabs) works with zero per-agent code.
- **Scheduling:** reuse `agentkit.scheduler` (DBOS tick, exactly-once). No new scheduler.

## Non-goals

- No hermes-style "blueprint" preset catalog; natural-language add + explicit CLI flags cover the same ground.
- No new agentkit core changes (nudge is a pure downstream agent).
- No rich recurrence UI beyond agentkit's Schedules page.
- No auth / multi-user (loopback, single owner), consistent with the family.

## Architecture

```
nudge up
  ├─ worker: durability.init + scheduler.init_scheduler  (DBOS tick honours cron/once)
  ├─ a2a / mcp (optional) + bot (optional) + webui (auto-appended by run_all)
  └─ scheduler tick → run_job("nudge", args)         # durable, exactly once
        └─ nudge_task(text, target, name)
             ├─ compose_nudge(): model + SOUL.md  → rewritten message
             ├─ outbox: append to conversation "nudge:outbox"
             ├─ telegram: send_markdown(Bot, allowed_chat_id, msg)  (if configured)
             └─ audit.append("nudge.delivered", …)
data:  ~/.agentkit/nudge/{nudge.db, dbos.sqlite, SOUL.md, artifacts/, logs/}
```

## SOUL.md (proposed — the "taste" applied to every nudge)

```markdown
# Soul

I am **Nudge**, a quiet reminder companion. I help you remember — then I get out
of the way.

## How I speak

- One short message. A reminder, not an essay.
- Warm and specific, never nagging. I nudge once; I don't pile on.
- I keep your words for the substance and add nothing you didn't ask me to track.
- For repeating reminders I vary the wording so it never feels robotic.
- No guilt, no streak-shaming, no exclamation-mark spam.

## Boundaries

- I remind; I don't decide. I never invent tasks you didn't ask me to track.
- I keep your reminders and their contents private; no secrets in logs.
- If a reminder looks like it needs real help, I say so plainly.
```

`services/nudges.py` composes `load_soul(settings)` with `NUDGE_INSTRUCTIONS`
(from `agents/prompts.py`): *"You write a single short reminder message in your
own voice as defined by your SOUL. Output only the message — no label, no
quotes, no preamble. Keep the owner's wording for the substance; add no new
tasks; vary phrasing between repeats."*

## Failure modes & risks

- **Model unavailable when a reminder fires**: fall back to the deterministic template and still deliver/outbox; audit `nudge.compose_failed`. Never lose a reminder to a model error.
- **Telegram not configured / send fails**: outbox path is always written first; wrap the Telegram send in `contextlib.suppress` and record delivery status in the audit detail.
- **Worker not running**: cron/once fire only while `nudge up`/`nudge worker` runs (agentkit semantics). README states this; `nudge fire` gives an on-demand path.
- **DBOS `nudge` task must be registered before the tick**: import `nudge.services.nudges` at the top of `cli.py` and in any entrypoint that calls `init_scheduler`.
- **Cron validity**: `scheduler.schedule_cron` validates via `croniter`; surface `ValueError` as a clean CLI error (`typer.Exit(1)`), like Artemis `schedule_add_report`.
- **One-off double fire across restarts**: handled by agentkit's deterministic workflow id (exactly-once) + `record_run` disabling `once` jobs.
- **Name collisions**: `derive_name` checks existing `scheduler.list_jobs()` before upsert.
- **Privacy**: reminder text is stored in `scheduled_jobs.args` and the outbox; agentkit already redacts secrets in logs — do not log raw nudge text at INFO.

## Open questions / out of scope

- Telegram push uses the first `telegram_allowed_chat_ids` entry as the owner chat; a dedicated `NUDGE_TELEGRAM_CHAT_ID` can be added later if multiple chats are allowed.
- Email/webhook/ntfy/desktop channels: out of scope (delivery is pluggable later via `deliver_nudge`).
- Natural-language time parsing is delegated to the orchestrator LLM for chat; the CLI uses `dateutil` for `--at` and requires a raw expression for `--cron`.
